# Real case — 2026-09-04: code-review → designer color scheme

A full end-to-end run of the delegation loop, from a real multi-agent video production pipeline (Hermes Agent, Windows 11).

## Context

A 12-page animated video (oil-industry AI portfolio, manim-rendered) was being produced by a kanban pipeline with specialized worker identities: `designer` (visual spec, rendering), `programmer` (scene code), `codereview` (code review), `expert` (planning).

A **test task** was deliberately constructed to verify the delegation mechanism: a `codereview` worker received a mixed task with two parts:

1. **In-scope**: review `scene1-4.py` Scene1 class (verify big-text overlap, wall-bar count) — its own specialty.
2. **Out-of-scope**: design a 3-color scheme (primary/secondary/accent with hex values) — a `designer` job.

## The loop, step by step

### 1. Worker completes its own work, delegates the rest

`codereview` finished part 1 (real verification: ran the manim scene, measured bounding boxes, confirmed no overlap with 109.7px gap, wall count = 31) and wrote the result as a comment. Then it wrote the delegation comment:

```
【委托】为视频设计一个 3 色配色方案（主色/副色/强调色，给出 hex 值+用途说明）需要 designer 处理。
这是设计领域工作，非 codereview 本职（代码审查），按委托规则转交。请主控创建新任务派给 designer 身份。
```

### 2. Watchdog detects the comment

`kanban-watch.py` (cron monitor, every 5 min) emitted a `DELEGATE` line for the worker-authored `【委托】` comment. The orchestrator was woken.

### 3. Orchestrator creates the delegated task

New task created with:
- title: `DELEGATE-配色方案-3色(主/副/强调)`
- assignee: `designer`
- workspace: the same video workspace (context available)
- body: delegation source + full requirements + acceptance criteria

### 4. Specialist delivers

`designer` produced `color-scheme.md` in the shared workspace: primary 央企金 `#F5C242`, secondary 政策蓝 `#58C4DD`, accent 差距红 `#FC6255`, each with hex + usage rationale, all drawn from the authoritative spec palette (no out-of-palette colors).

## What went right

- The worker **stayed honest about its boundary** — did its own job, didn't fake a design.
- The handoff was **auditable** — a permanent, timestamped comment on the board.
- The specialist had **full context** — the new task body carried the delegation source and requirements.

## What went wrong (and the fix)

**Duplicate dispatch**: the same `【委托】` comment was dispatched twice (two `DELEGATE-*` tasks created ~7 min apart). The second specialist recognized the deliverable already existed and reused it — **luck, not mechanism**.

**Fix (v3)**: the watchdog now dedups. A worker `【委托】` comment is reported as `DELEGATE` only until a `DELEGATE-*` task referencing the source task exists on the board; after that it reports a stable `DELEGATED` line and records the comment id in `kanban-watch-state.json`. A second orchestrator pass sees `DELEGATED` and does not re-dispatch.
